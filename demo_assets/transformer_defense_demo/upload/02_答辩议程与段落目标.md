# Transformer 小型答辩：议程与段落目标

## 会议目标

在 90 秒左右讲清 Transformer 的提出动机、自注意力、位置编码、多头注意力、优势与局限。会议助手应持续判断当前讲到哪一段，未完成当前段时先提示缺失点，不要提前收尾。

## 议程状态

### 1. 问题背景

应覆盖：

- RNN/LSTM 按时间步顺序计算；
- 训练并行度受限；
- 长距离信息传递路径较长；
- Transformer 用注意力让任意位置直接交互。

完成标志：已经明确说明“为什么需要从循环结构转向注意力”。

自然过渡：

> 那么，注意力具体怎样决定当前词应该关注谁？

### 2. 自注意力与 Q、K、V

应覆盖：

- Query 表示想寻找什么；
- Key 用于匹配；
- Value 是被聚合的信息；
- Query 与 Key 形成权重，再对 Value 加权汇总。

完成标志：已经讲清 Q、K、V 的直观含义和加权汇总过程。

自然过渡：

> 自注意力解决了“关注谁”，但模型还需要知道内容原本处在什么位置。

### 3. 位置编码与多头注意力

应覆盖：

- 自注意力本身不包含先后顺序；
- 位置编码向输入注入顺序信息；
- 多头注意力使用多组投影，在不同表示子空间建模关系。

完成标志：已经明确说出 Transformer 不是没有顺序信息。

自然过渡：

> 这些设计带来了明显优势，但同时也付出了计算代价。

### 4. 优势与局限

应覆盖：

- 训练并行度高；
- 任意位置直接交互，适合长距离关系建模；
- 标准全局注意力对长序列存在近似平方级计算和内存开销；
- 自回归解码仍逐步进行。

完成标志：优势和局限都已经出现，不能只讲优势就进入总结。

自然过渡：

> 因此，Transformer 的核心贡献可以归纳为三个关键词。

### 5. 总结

应覆盖：

- 注意力取代循环，成为主要交互方式；
- Q、K、V 动态选择上下文；
- 位置编码和多头机制补齐顺序与多视角建模。

只有前四段都完成后，才可以提示致谢或接受提问。
