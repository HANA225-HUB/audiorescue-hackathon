# 逐镜头录制方案

## 故事主线

学生在复杂环境中完成 Transformer 小型答辩：AudioRescue 先恢复实时麦克风，再用会前资料和会议上下文辅助发言。整片不需要一镜到底，建议拆成 6 段录制，再自然剪接。

## 画面布局

- 主画面：会议软件、摄像头或屏幕录制；
- 产品画面：AudioRescue 网页；
- 悬浮窗：保持在右上角，不遮挡人物面部和关键按钮；
- 最好准备第二台设备或队友账号作为接收端，证明对方听到的是 BlackHole 输出；
- 全程戴耳机，避免回声；
- 背景噪声使用稳定风扇、空调或连续键盘声，不使用音乐和他人说话录音。

## 时间轴

| 时间 | 画面 | 操作 | 必须让观众看懂的证据 |
|---|---|---|---|
| 0:00–0:20 | 真人或会议摄像头 | 开启稳定噪声并说开场 | 真实痛点：噪声、小声、答辩压力同时存在 |
| 0:20–0:45 | 设备与实时引擎 | 指向输入麦克风、BlackHole 和模式 | 这是实时链路，不是上传文件后处理 |
| 0:45–1:15 | 产品页与接收端并排 | 同一句话先 `raw` 后 `enhanced` | 接收端噪声下降、人声保留；两遍条件一致 |
| 1:15–1:35 | 产品页与接收端 | 安静环境，同一句轻声先 `raw` 后 `quiet` | 小声模式提高可懂度，不削弱人声 |
| 1:35–2:00 | 会前预设与资料列表 | 展示字段和三份 Markdown，开始新会议 | 上下文和资料在发言前已经准备好 |
| 2:00–3:25 | 会议画面 + 悬浮窗 | 完成小型答辩，两次请求下一段建议 | 建议承接当前内容；中途不提前致谢 |
| 3:25–4:05 | 悬浮窗特写 | 输入位置编码问题并生成回答 | 回答短、正确、基于上传资料 |
| 4:05–4:35 | 产品全局画面 | 总结四个能力 | 完成“声音恢复 + 会议辅助”闭环 |

## 分段拍摄建议

### A. 声音对比段

- 固定麦克风位置、说话方向和背景噪声；
- 两次使用完全相同的测试句；
- 模式切换后等待一秒再说；
- 录音端不要开自动增益或额外降噪；
- 不加背景音乐，不做后期音量匹配。

### B. 会前预设段

- 开拍前已经填好所有字段，不在正片中逐字输入；
- 鼠标依次扫过“会议名称、场景、目标、议程、资料”；
- 停留 3–5 秒，让观众看到三份资料已选择；
- 点击“开始新会议”后，等待悬浮窗稳定再切画面。

### C. 会议助手段

- 浏览器退到后台，会议画面成为主体；
- 悬浮窗保持可读，字号不要太小；
- 发言采用短句，句间停顿 0.5–1 秒，有利于 ASR 分段；
- 第一次建议在 Q/K/V 讲完后触发；
- 第二次建议在优势讲完、局限尚未讲时触发；
- 保留建议生成的真实等待，但超过两秒的空白可在后期压缩。

### D. 提问段

- 当前版本用悬浮窗输入远端问题；
- 主问题固定为位置编码问题，成功率和观众理解度最高；
- 可选压力问题用于证明系统不编造数字；
- 回答出现后停留 3 秒，再由讲者用自然语气回答。

## 后期字幕建议

只强调四个词，避免屏幕过满：

- 实时降噪
- 小声增强
- 会前知识预载
- 悬浮会议提示

片尾固定文案：

> 让复杂环境中的每一次会议，都能听得清、说得稳、答得上。

## 不建议拍进正片的内容

- 安装依赖和启动终端；
- API Key、环境变量和本机路径；
- fixture 页面或假数据；
- 大段等待、报错重试和临时调参；
- 对系统当前不具备的“自动听见远端耳机音频”能力做暗示。
