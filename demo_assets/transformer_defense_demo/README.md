# AudioRescue 正式 Demo 包：Transformer 小型答辩

这套材料用于录制一条约 5 分钟的正式产品 Demo。核心故事是：

> 一名学生身处嘈杂或必须小声说话的环境，仍然需要完成一场 Transformer 小型答辩。AudioRescue 先把麦克风声音实时恢复到适合会议的状态，再根据会前预设和参考资料，通过悬浮窗提供字幕、下一段建议和提问回答。

这个场景比单独演示降噪或单独聊天更完整，因为它能在一条连续流程中证明：

1. 真实麦克风输入可以实时降噪，并输出到 BlackHole 虚拟麦克风；
2. 安静场景下可以切换到小声增强；
3. 会前资料会在会议开始前完成解析和知识预载；
4. 浏览器退到后台后，悬浮窗仍能给出与当前议程相符的下一段建议；
5. 对方问题可以在悬浮窗中输入，并基于资料生成简短回答。

## 文件怎么用

### 上传到系统

在“会议参考资料”中上传 `upload/` 目录中的三个文件：

- `01_Transformer核心知识.md`
- `02_答辩议程与段落目标.md`
- `03_预期提问与依据.md`

这些文件是专门给会议助手读取的。它们包含稳定知识、汇报顺序和回答边界，不包含本机路径、API Key 或私人信息。

### 录制人员自己看

`operator/` 目录中的文件不要上传给会议助手：

- `01_系统预设.md`：逐项复制到网页表单；
- `02_完整口播稿.md`：正式录制时照着练，不建议全程逐字念；
- `03_逐镜头录制方案.md`：摄影、操作和画面安排；
- `04_开拍检查与故障预案.md`：录制前最后核对。

## 推荐演示顺序

1. 用同一句固定测试语，对比 `raw` 与 `enhanced`；
2. 在安静环境中，用同一句轻声测试语展示 `quiet`；
3. 展示已经填写的会前预设和三份已选择的资料；
4. 点击“开始新会议”，让悬浮窗保持在会议画面上方；
5. 完成 70–90 秒 Transformer 小型答辩；
6. 在两个预设位置点击“立即生成下一段建议”；
7. 在“对方刚刚说了什么”中输入位置编码问题并生成回答；
8. 用一句产品总结收尾。

## 诚实演示边界

- `AUDIORESCUE_UI_FIXTURE=0` 才是真实链路；fixture 模式不能证明真实降噪、转写或模型建议。
- 当前 ASR 主要听本机麦克风链路。戴耳机时不能宣称系统已经自动听见远端参会者；正式 Demo 中应把对方问题输入悬浮窗。
- 原声与增强对比段不要后期降噪、均衡或音量归一化，否则会破坏对比可信度。
- 会议软件若自带降噪，应关闭或降到最低；如果无法关闭，使用第二设备或本地录音工具直接录制 BlackHole 输出。
- 不展示 API Key、终端历史、私人文件名或本机绝对路径。
