# 数据集与演示样例制作手册

> 版本：2026-07-14 / 公共版。本文只描述通用 schema、合成示例和本地私有 spec 流程，不记录真实成员、参考文本、样例 ID、文件名、数量矩阵或候选映射。

## 1. 原则

- 仓库只跟踪 `configs/dataset_spec.example.json`，其中所有值都是明显合成的 neutral values。
- 实际采集矩阵必须写入本地 spec，并使用 `.gitignore` 中的 local/private 命名模式保存。
- 初始化、构建、校验三类工具都从同一个 spec 读取字段、路径、split、参考文本、授权 token 和候选标记。
- 未提供私有 spec 时，工具只使用合成模板，不推断真实团队数据。
- 错误信息只报告字段、类别和固定操作提示，不回显参考文本、绝对路径、spec 内容或私有样例名。

## 2. Spec 结构

`configs/dataset_spec.example.json` 展示最小公共结构：

- `dataset_version`：本地数据版本字符串。
- `sample_rate`、`channels`、`sample_width_bytes`：标准化 WAV 契约。
- `consent_tokens.pending` 与 `consent_tokens.approved`：开发态和正式评测态 token。
- `clean_recordings`：干净语音 master，包含 `id`、`speaker_id`、`sentence_id`、`reference_text`、`path`、`split`。
- `noise_recordings`：噪声 master，包含 `id`、`noise_type`、`path`。
- `mixes`：可控混合样例，按 `clean_id` 和 `noise_id` 引用 master，并声明 `sample_id`、`split`、`snr_db`、`snr_label`、`path`、`is_locked`、`is_demo_candidate`。
- `clean_controls`：直接复用 clean master 的控制样例。
- `real_recordings`：没有对齐 clean/noise 分量的真实录制样例。

所有路径必须是相对路径，必须留在授权数据 root 内，不允许 traversal、绝对路径或 symlink。

## 3. 本地流程

1. 复制 example spec 到本地 private/local 命名的 JSON 文件。
2. 用 neutral 字段结构替换为本地真实配置；该文件不得提交。
3. 初始化工作区：

```powershell
python -m scripts.init_dataset --root data_local --spec <local-spec>
```

4. 将源录音只读保存到 `source_original/`，把标准化后的 48 kHz mono PCM16 WAV 放入 spec 声明的相对路径。
5. 填写 `recording_metadata.csv`，记录源文件和标准化 WAV 的 SHA-256、授权状态和必要元数据。
6. 构建 manifest 和可控混合：

```powershell
python -m scripts.build_dataset --dataset-root data_local --spec <local-spec>
```

7. 正式评测前必须使用 approved token，并让 validator 通过：

```powershell
python -m scripts.validate_dataset data_local --spec <local-spec>
```

## 4. Manifest 契约

公共 manifest 字段保持稳定：

```text
sample_id, dataset_version, split, speaker_id, sentence_id,
reference_text, reference_normalized, source_type, clean_path,
noise_path, mixed_path, noise_type, noise_source, consent_or_license,
snr_db, mix_seed, noise_offset_seconds, mix_alpha, final_gain,
sample_rate, channels, duration_seconds, recording_device,
recording_distance_cm, sha256, is_demo_candidate, is_locked, notes
```

Validator 会检查：

- 字段完整、ID 唯一、主路径唯一。
- SHA-256 与主音频一致。
- consent/license token 为 spec 的正式 token。
- split、source_type、路径、参考文本和候选标记与 spec 一致。
- WAV 格式、时长、静音、削波和混合峰值符合策略。
- 路径在授权 root 内，拒绝 traversal、绝对路径和 symlink。

## 5. Holdout 与一次性原则

Spec 中 `is_locked=true` 或团队定义为 holdout 的 split 不应用于调参。正式评测应在代码、配置、manifest、授权、Git commit 和运行环境都冻结后执行，并保留不可变记录。

## 6. Demo Assets

`demo_assets/` 只放公开可展示、已脱敏、可再分发的样例。样例名应使用 neutral role，例如 `demo_role_1.wav`，不要暴露真实候选 ID、成员、参考文本、采集地点或本地路径。

## 7. 发布检查

- 本地 spec 未被 Git 跟踪。
- 文档、代码和测试只包含 neutral example values。
- manifest 中所有路径均为相对路径。
- `reference_text` 只用于指标或人工核对，不进入模型 prompt。
- `scripts.validate_dataset` 对 traversal、symlink、hash、split、consent/license 错误均 fail closed。
