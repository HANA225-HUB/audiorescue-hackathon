# 07｜公开数据与演示样例指南

> 本文件是公开仓库版本，只描述数据治理、授权和演示样例选择原则。
> 具体台词、成员映射、录音文件名、噪声矩阵、评测划分、数量、路径、哈希和参考文本均保存在本地私有台账或私有 spec，不进入 Git，也不在 PR、Issue、截图或日志中复述。

---

## 1. 公开边界

公开文档只能使用以下中性表述：

- `approved short sample`
- `private ledger`
- `private data root`
- `synthetic fixture`
- `demo candidate`
- `reserved evaluation set`
- `team-owned recording`

公开文档不得写入：

- 私有参考正文、转写文本或可逆摘要；
- 成员到样例、噪声或场景的映射；
- 真实录音文件名、样例编号、分组名、路径或数量；
- 冻结评测集细节、一次性评测输入、听感结论或指标；
- 服务器、缓存、模型权重、凭据或本机绝对路径；
- 任何能让外部读者重建私有数据集的矩阵、表格或编码。

历史 Git 记录不通过本文件处理。若需要历史清理，必须由仓库负责人另行决策；普通 PR 不做 force-push 或历史重写。

---

## 2. 数据类别

| 类别 | 公开说明 | 允许用途 | 公开限制 |
|---|---|---|---|
| synthetic fixture | 由测试代码生成或仓库内公开的小型合成素材 | 单元测试、UI 状态、离线资源交付 | 不代表真实增强、识别质量或用户效果 |
| approved short sample | 已获授权的短音频，详情在私有台账 | 本地 smoke、人工验收、演示候选 | 不公开文本、文件名、路径、成员映射或指标明细 |
| private ledger | 本地私有授权与样例台账 | 记录授权、哈希、用途和审核状态 | 不提交 Git，不贴到 Issue，不放进截图 |
| reserved evaluation set | 最终保留评测数据 | 冻结后一次性评估 | 不用于调参、试跑、公开复现或公开比较 |

---

## 3. 私有台账最低字段

私有台账可包含以下字段，但字段值不公开：

- neutral sample id;
- consent status;
- source owner or approver;
- intended use;
- input media hash;
- normalized media hash;
- duration bucket;
- language;
- reference availability;
- review status;
- notes for local operators.

公开报告只可写“授权短样例已通过本地台账检查”或“仍待人工验收”，不得写具体样例内容。

---

## 4. Synthetic Fixture 规范

仓库内 synthetic fixture 应满足：

- 不含真实人声、私有文本或成员身份；
- 可由代码重建或可明确说明来源；
- 文件体积小，适合单元测试；
- 只用于 I/O、页面状态、错误降级、下载和离线资源检查；
- 文档中明确说明“不代表模型效果”。

示例命名可以使用：

```text
synthetic_tone_short.wav
synthetic_noise_short.wav
fixture_original.wav
fixture_mixed.wav
fixture_visualization.png
```

这些名字只是公开占位，不对应任何私有素材。

---

## 5. 演示样例选择原则

主演示候选必须在本地私有台账中完成：

1. 授权确认；
2. 输入格式检查；
3. 私有参考是否可用的记录；
4. 三人或指定评审的人工听感记录；
5. 处理耗时记录；
6. 失败回退素材准备；
7. 公开摘要审查。

公开摘要只描述类别和状态，例如：

```text
demo candidate A: approved short sample, local rehearsal pending
demo candidate B: approved short sample, boundary case candidate
fallback: precomputed local artifact, same code/config version
```

不得公开原始或增强后文本、成员身份、真实文件名、具体场景映射、私有路径或逐样例指标。

---

## 6. 评测与调参纪律

- 开发只能使用 synthetic fixture 和已授权开发样例。
- 保留评测数据只在冻结后使用，不用于参数选择、展示挑样或公开调试。
- 如果真实样例效果不好，公开结论写成“仍待人工验收”或“该候选未通过”，不得补写、改写或伪造转写。
- 人耳验收和 CER 等指标必须由 C 汇总，公开只发布安全摘要。
- 任何可复现私有数据内容的截图、表格、URL、日志或文件名都不得进入 PR 或 Issue。

---

## 7. 离线演示资产包

最终演示机可以准备本地私有资产包，公开文档只描述结构，不给真实路径：

```text
private_demo_pack/
  inputs/
  precomputed/
  safe_summaries/
  operator_notes/
```

资产包要求：

- 只保存在本地私有位置；
- 不提交 Git；
- 不在 PR 截图或 Issue 中展开；
- 不含凭据或服务器信息；
- 由 C 确认授权和版本一致性。

---

## 8. 公开报告模板

推荐公开报告只保留以下字段：

```text
sample_category: approved short sample
run_mode: local/offline
fixture_used: true/false
result_state: success/partial/failed
elapsed_time_bucket: safe summary
tests: command and pass count
privacy_review: PASS/FAIL
known_risks: safe summary
```

不要加入原始异常正文、绝对路径、token URL、缓存路径、私有文本或真实音频名称。

---

## 9. Go / No-Go

公开 Go 条件：

- PR head 和测试状态明确；
- fixture 与真实样例边界明确；
- 真实用户效果仍由人工验收决定；
- 页面失败状态不会伪装成完整成功；
- 公开文档不含私有数据细节。

公开 No-Go 条件：

- 文档含有私有文本、文件名、映射、路径或受保护评测细节；
- 文档建议现场联网下载模型或裸升级依赖；
- 文档把 synthetic fixture 当作真实效果证据；
- 文档宣称未合并 PR 已进入 main 或比赛 ready。
