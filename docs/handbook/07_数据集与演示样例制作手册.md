# 07｜数据集与演示样例制作手册

> 项目：听清又听懂·智能音频急救台
> 版本：2026-07-14 / `AudioRescue-CN-Mini-v1`
> 用途：当前两天黑客松的开发、冻结评测和现场演示
> 重要前提：本项目只调用预训练模型推理，**不训练 DeepFilterNet、Whisper 或 CLAP**。

---

## 0. 最终数据集决定

本项目不下载大型中文训练语料。只使用三层数据：

| 层 | 数据 | 是否必需 | 用途 |
|---|---|---|---|
| 主数据 | 团队自建 `AudioRescue-CN-Mini-v1` | **必需** | 中文 CER、A/B、演示、边界和离线回归 |
| 外部检查 | VoiceBank-DEMAND 官方测试集 | 可选，P0 稳定后 | 英文配对 clean/noisy sanity check，不用于主演示 |
| P1 事件 | ESC-50 的 4 类子集 | 仅 CLAP Go 后 | `siren / keyboard typing / clapping / car horn` 标签检查 |

明确不做：

- 不下载 AISHELL-1 全量；官方包约 15GB，已经超过本机当前约 12GB 可用空间；
- 不下载完整 7.4GB DEMAND；VoiceBank-DEMAND 测试集已提供轻量的配对 clean/noisy 检查；
- 不收集数小时语料；
- 不把演示音频当作“训练集”；
- 不为让一条样例变好而反复修改它的参考文本或混音参数。

---

## 1. 为什么主数据必须自建

当前产品要展示的是中文录音增强后，Whisper 是否更容易转写。公开语料不能同时保证：

- 中文台词完全已知；
- 场景与风扇、键盘、道路噪声匹配；
- 现场可以合法播放和随包分发；
- 音频足够短且效果可解释；
- 能保存干净轨、噪声轨和目标 SNR；
- 三名成员能够亲自确认听感。

因此主数据由团队自己录制。公开数据只承担外部 sanity check，不替代中文演示集。

---

## 2. `AudioRescue-CN-Mini-v1` 的精确规模

### 2.1 原始素材

- 3 名说话人：A、B、C；
- 每人录 3 句固定台词：共 9 条干净语音；
- 3 段自录噪声底：风扇、键盘、道路交通；
- 每段噪声至少 45 秒，目标 60 秒；
- 3 条真实带噪录音：噪声与说话同时现场录制。

### 2.2 可控混合

每条干净语音只绑定一种噪声，但生成三个 SNR 版本：

```text
9 条干净语音 × 3 个 SNR（+5 / 0 / -5 dB）＝27 条可控混合语音
```

最终数据规模：

```text
9 clean masters
3 noise stems
27 controlled mixtures
3 real noisy recordings
3 clean-control test cases（直接复用三条 clean，不复制文件）
```

预计原始数据、混合数据、增强输出、转写和图片总量控制在 1GB 内；数据本体通常只需约 100–300MB。

## 3. 三句固定中文台词

三个人都录下面三句，每句只录一条最终版本：

| 编号 | 固定台词 | 重点 |
|---|---|---|
| S01 | 今天下午三点，我们在实验室讨论语音处理项目的最终方案。 | 时间、地点和普通叙述 |
| S02 | 请记录会议中的三个重点：数据来源、模型效果和系统稳定性。 | 指令、并列结构、核心产品词 |
| S03 | 如果现场网络中断，系统仍然可以在本地完成音频增强和文字转写。 | 较长句、条件关系、主演示故事 |

规则：

- 参考文本直接复制本表，不靠听写重新输入；
- Whisper 的原始输出不得人工修改；
- CER 规范化可以统一删除标点和空格，但前后两轨使用完全相同规则；
- 不把参考台词传入 Whisper `initial_prompt` 或其他提示参数；
- 如果说话人读错字，重录；不能修改参考文本去迎合口误。

---

## 4. 说话人—台词—噪声分配

使用下面固定拉丁方分配，保证冻结集的三条台词覆盖三类噪声：

| 说话人 | S01 | S02 | S03 |
|---|---|---|---|
| A | 风扇 | 键盘 | 道路交通 |
| B | 键盘 | 道路交通 | 风扇 |
| C | 道路交通 | 风扇 | 键盘 |

每个单元格都生成 `+5dB / 0dB / -5dB` 三条混合音频。

分割规则：

- `dev`：S01、S02，共 18 条混合；允许用于选择 Whisper `tiny/base` 和 dry/wet 强度；
- `locked_test`：S03，共 9 条混合；在配置冻结前不得用于调参；
- `real`：3 条真实现场录音；用于产品展示与能力边界，不做需要干净波形的指标；
- `clean_control`：A/B/C 的三条 S03 干净轨；用于检查增强是否破坏本来清楚的语音。

## 6. 录音标准

### 6.1 干净语音

- 优先在安静房间录制；
- 麦克风距离约 20–30cm，方向和距离保持不变；
- 关闭设备自带“人声隔离”“会议降噪”等不可控处理；
- 开头和结尾各留约 0.5 秒；
- 正常自然语速，不刻意逐字播音；
- 峰值建议低于 -3dBFS，不得削波；
- 最终统一为 WAV、48kHz、单声道、PCM 16-bit；
- 保留原始录音，不直接在原文件上覆盖转码。

### 6.2 噪声底

每段噪声 45–60 秒，并且尽量不包含可辨认的私人谈话：

| 噪声 | 录制方式 | 目标能力 |
|---|---|---|
| fan | 固定距离录风扇/空调，保持档位不变 | 稳态噪声，主演示优先 |
| keyboard | 连续自然打字，轻重按键混合 | 瞬态非稳态噪声，边界样例 |
| traffic | 在安全窗边或路边录车辆声，不录行人私密对话 | 宽带复杂环境噪声 |

每段噪声记录设备、位置、日期、录制人和授权状态。

### 6.3 真实带噪录音

三条即可：

1. A：说 S01，同时开启风扇；
2. B：说 S02，同时由另一成员敲键盘；
3. C：说 S03，在安全窗边保留道路噪声。

真实录音有人工参考台词，可以比较 CER；但没有严格对齐的干净波形，因此不计算 PESQ、STOI 或真实 SNR。

## 7. 混音方法

内部使用 float32，先把 clean 与 noise 转成相同采样率、单声道。对干净语音裁掉过长的头尾静音，但保留约 0.5 秒自然空白。

目标 SNR 的缩放：

```text
P_s = mean(clean²)
P_n = mean(noise²)
alpha = sqrt(P_s / (P_n × 10^(SNR_dB / 10)))
mixed = clean + alpha × noise
```

等价写法：

```text
alpha = RMS(clean) / RMS(noise) × 10^(-SNR_dB / 20)
```

注意：

- 噪声长度不足时重新选择片段，不简单循环制造周期性；
- clean 与 noise 应先去除明显直流偏置；
- `P_n` 接近 0 时直接报错；
- 噪声片段起始位置由固定随机种子决定并写入 manifest；
- 不分别归一化混合后的语音和噪声，否则目标 SNR 会被破坏。

防削波：

```text
peak = max(abs(mixed))
final_gain = 1.0                         if peak <= 0.98
final_gain = 0.98 / peak                 if peak > 0.98
mixed_out = mixed × final_gain
clean_reference_aligned = clean × final_gain
noise_component_aligned = alpha × noise × final_gain
```

必须保存 `alpha`、`final_gain`、噪声偏移和随机种子。

## 10. 防止“挑样例式评测”

虽然项目不训练模型，仍需防止在九条测试样例上无限调参：

1. A、B 只看 `dev` 的 18 条混合；
2. C 在参数冻结前保管 `locked_test` 的 manifest/音频；
3. 锁定 `Whisper model + language + strength + normalization`，保存 `config_frozen.json`；
4. 一次性运行 9 条 `locked_test`；
5. 报告改善、持平、变差数量和 CER 中位数，不只报告最好的一条；
6. 可以从冻结集选择最适合现场讲解的一条，但必须同时保留完整统计；
7. 如果根据测试集内容再次调参，将版本标为 `v1-tuned`，不得继续称“未见测试集”。

修复崩溃、路径或文件损坏后可以重跑；根据某条内容改变增强强度属于调参。

## 13. 为什么现在不用 AISHELL-1 和完整 DEMAND

### AISHELL-1

AISHELL-1 是正规的普通话语料：官方 OpenSLR 页面列出 Apache 2.0、400 名说话人、16kHz 录音，但主数据包约 15GB。本项目不训练 ASR，且本机当前只有约 12GB 可用空间，因此现在下载会增加失败风险而没有直接演示收益。

未来需要大规模中文 ASR 验证时再使用：[OpenSLR SLR33](https://www.openslr.org/33/)。

### 完整 DEMAND

DEMAND 官方数据包含多环境、16 通道噪声，并同时提供 48kHz/16kHz版本，许可为 CC BY-SA 3.0；完整记录约 7.4GB。当前只需要三类噪声，自录 noise stems 更快、更贴近现场，VoiceBank-DEMAND test 也已覆盖轻量外部检查，因此不下载全量。

未来需要更多环境噪声时按单个 zip 下载，不要整包拉取：[DEMAND Zenodo](https://zenodo.org/records/1227121)。

## 14. 评测输出

每条样例保存：

```text
status
runtime stages
transcript_before_raw
transcript_after_raw
reference_raw
normalized texts
CER before / after
substitution / deletion / insertion
output peak / clipped ratio
warnings
human listening result
```

CER：

```text
CER = (S + D + I) / N
CER_delta = CER_before - CER_after
```

`CER_delta > 0` 才表示增强后的转写更好。

冻结集必须报告：

- 9 条成功处理数量；
- CER 改善/持平/变差数量；
- Before/After CER 中位数；
- 三种噪声分别结果；
- 三个 SNR 分别结果；
- 至少一条负例或“没有改善”的诚实说明。

没有足够样本时不做显著性结论，不写“整体准确率显著提升”。

## 15. 主演示样例选择规则

预先指定候选，而不是上台前乱翻文件：

| 角色 | 首选 | 目的 |
|---|---|---|
| 主样例 | `mix_spkB_s03_fan_snr000.wav` | 稳态风扇、0dB，通常改善稳定；必须有 CER 和盲听证据 |
| 边界样例 | `mix_spkC_s03_keyboard_snrm05.wav` | 瞬态键盘、-5dB，用于说明能力边界 |
| 干净控制 | `clean_spkA_s03.wav` | 证明系统不会为了去噪明显破坏干净语音 |
| 真实样例 | `real_spkC_traffic_r01.wav` | 展示真实录制，但不伪造 clean-reference 指标 |

最终主样例必须同时满足：

- 连续运行三次成功；
- 至少 2/3 成员盲听认为增强后更清楚；
- 音量没有明显偏置；
- CER 改善，或至少关键词与人工可懂度有真实证据；
- 10–15 秒热运行能在演示门槛内完成。

若首选没有改善，允许换到冻结集中的另一条，但测试报告必须保留完整九条结果和换样理由。
