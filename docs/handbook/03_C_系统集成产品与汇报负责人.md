## 5. 你必须冻结的公共契约

唯一 UI 入口：

```python
def process_audio(
    input_path: str,
    strength: float = 0.75,
    enable_events: bool = False,
    reference_text: str | None = None,
    force_recompute: bool = False,
) -> ProcessResult:
    ...
```

必须使用总手册中的公共类型：

```text
AudioMeta
TranscriptResult
CerResult
EventResult
RuntimeStats
WarningItem
ProcessResult
```

状态含义不可漂移：

- `success`：增强、双轨转写和核心可视化全部完成；
- `partial`：增强成功，但 ASR 或可视化至少一项失败，仍可播放增强轨；
- `failed`：输入无法解码，或没有得到可播放增强音频；
- CLAP 关闭/失败只产生 `EVENTS_SKIPPED`，不能把 P0 从 `success` 降级。

每个 `ProcessResult` 必须带 `job_id`、配置快照、分阶段耗时、警告和真实输出路径。示例 JSON 只能用于前端开发；正式报告的数字必须来自最终演示机。

## 6. 集成顺序

### 6.1 第一次集成：只求闭环

1. 用 B 的虚拟结果确认页面能渲染 `success/partial/failed`；
2. 用 A 的标准化函数处理一个 10 秒 WAV；
3. 调用增强，确认文件存在、非空且可播放；
4. 顺序调用原轨/增强轨 Whisper；
5. 生成最简单的前后文本与对照图；
6. 聚合 `ProcessResult`；
7. UI 只替换数据源，不改模型代码；
8. 保存第一个可回滚版本。

第一次闭环不做 CLAP、导出报告、动画或流式录音。

### 6.2 第二次集成：补齐公平与错误

- 原始与增强轨使用同一 Whisper 模型、语言和解码参数；
- 有人工参考文本才算 CER；
- 波形和声谱图使用相同坐标/色标；
- 任一阶段异常转成稳定警告码；
- 每次任务写独立目录，防止上一条音频与本次文本串线；
- 固定样例缓存必须包含输入哈希、模型、强度、语言和代码/配置版本；
- 使用缓存时页面明确显示，不伪装新推理。

### 6.3 第三次集成：演示与离线

- 锁定主演示样例 A、边界样例 B 和可选样例 C；
- 在演示机上测冷启动与至少三次热运行；
- 关闭网络重启并处理样例；
- 完成一段带声音的成功录屏；
- 运行错误文件、静音、超长和 ASR 单路失败测试；
- 从提交压缩包在新目录重现启动。

## 7. `pipeline.py` 的实现清单

按固定顺序编排：

```text
validate request
→ create job directory
→ normalize + inspect
→ enhance + dry/wet + output validation
→ transcribe original
→ transcribe enhanced
→ diff and optional CER
→ waveform/spectrogram
→ optional events from original only
→ aggregate status/warnings/runtime
→ persist result.json and log
→ return ProcessResult
```

硬性要求：

- 使用单调时钟计时；
- P0 推理顺序执行，不为省几秒并行抢内存；
- 不捕获所有异常后返回“成功”；
- 可恢复错误追加警告并保留已成功结果；
- 输出文件通过存在、大小、可解码和有限值检查后才能放进结果；
- 不在模块 import 时下载模型；
- UI 刷新或重复点击不能覆盖其他 `job_id`；
- 并发默认限制为 1，除非演示机实测通过。

## 8. CER、diff 与证据口径

你负责锁定一套中文规范化规则：Unicode 统一、约定标点/空白处理、英文大小写规则和数字保留方式。前后两轨与参考文本必须用同一规则。

只允许两类页面口径：

1. 有真实参考台词：显示字符数、Before/After CER、替换/删除/插入和百分点变化；
2. 无参考台词：只显示两次转写差异，并注明差异不等于 after 一定正确。

禁止：

- 用增强后 Whisper 文本当参考答案；
- 手工修正模型输出后再算 CER；
- 把“下降 10 个百分点”说成“准确率提升 10%”；
- 没有干净参考音频时伪造 PESQ/STOI/SNR 提升。

## 11. GPT-5.6 Sol 的使用方式

把它用在高价值全局任务：

- 审查总契约和文件所有权是否冲突；
- 同时阅读 A/B 交接、traceback 与调用链，定位跨模块错误；
- 对提交差异做回归风险审查；
- 检查测试是否真正覆盖声明；
- 压缩五分钟叙事、准备追问；
- 核对所有数字是否有测试证据。

不要让它消耗在几十轮 CSS 微调、重复装包或每个函数都从零生成；这些交给两位有近乎无限 GPT-5.5 额度的成员。
