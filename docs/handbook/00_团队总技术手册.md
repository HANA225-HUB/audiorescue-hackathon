# AudioRescue 团队总技术手册

## 1. 文档目的

本文是公开、稳定的项目总览。它描述软件架构、角色边界、验收门禁与交付方式，不包含真实素材、内部评测结构、个人环境或运行秘密。

## 2. 产品链路

```text
本地音频
  -> 输入校验与标准化
  -> 完整增强轨 + 可调混合轨
  -> 处理前/后双路转写
  -> 波形、频谱与文本差异
  -> 状态、告警和不透明本地交付地址
```

系统必须在任一阶段失败时返回可渲染的固定状态，而不是让界面崩溃或泄漏原始异常。

## 3. 架构

- `core/`：音频、增强、转写、指标、可视化和 pipeline。
- `ui/`：展示模型、文件暂存、本地交付与页面布局。
- `app.py`：单一界面入口。
- `configs/`：公开、可审查的运行配置。
- `tests/`：单元、契约、隐私与离线夹具测试。
- `docs/`：公开契约、演示与团队手册。

单一业务入口是 `core.pipeline.process_audio`。UI 只能通过公开 schema 使用结果，不能依赖内部临时文件结构。

## 4. 角色分工

### A：音频增强与转写

负责输入校验、标准化、增强、双路转写、音频级别证据和模型错误语义。详见 [A 手册](01_A_音频增强与转写负责人.md)。

### B：前端与交付

负责上传、参数、状态、播放器、图表、文本差异和本地文件交付。详见 [B 手册](02_B_前端交互与可视化负责人.md)。

### C：集成与产品

负责公共 schema、pipeline、跨模块契约、任务路由、冻结、回滚和公开证据。详见 [C 手册](03_C_系统集成产品与汇报负责人.md)。

## 5. 公共契约

### 输入

- 一个本地音频文件；
- 有界、有限的增强强度；
- 可选事件检测开关；
- 可选参考文本仅用于本地私有评测；
- 可选重新计算开关。

### 输出

`ProcessResult` 使用三态：

- `success`：核心产物完整且可交付；
- `partial`：部分阶段失败，但仍有安全、可解释的结果；
- `failed`：没有可用核心产物。

所有数字必须有限，所有路径只在进程内部使用。公开展示通过不透明本地地址访问经过重新验证的产物。

## 6. 失败与降级

- 输入无效：固定失败状态，不进入模型。
- 增强失败：不伪造增强结果。
- 单路转写失败：降级为 partial，另一轨仍可展示。
- 可视化失败：不影响已验证音频，但必须显示告警。
- 文件在注册后变化：注销地址、移除入口并降级。
- 未知异常：只记录类型与固定错误码，不透传原始消息。

## 7. 缓存与离线

缓存必须基于内容和公开配置构造键，并在命中时验证产物仍存在且有效。缓存命中、冷启动和设备类别应进入脱敏运行统计。

演示前完成依赖、FFmpeg 和模型资产准备。现场不下载模型、不升级依赖、不切换环境。详见 [离线演示手册](../OFFLINE_DEMO_RUNBOOK.md)。

## 8. 测试层级

1. 模块单测：纯函数、schema、错误码和边界值。
2. 合成夹具：pipeline、UI、交付和离线资源。
3. 组合验收：固定 heads、无冲突、全量测试和浏览器检查。
4. 真实模型 smoke：只证明技术链路可运行。
5. 用户效果测试：人工听测和真实使用体验，必须独立记录。

夹具、真实模型 smoke 与用户效果结论不得互相替代。

## 9. 隐私边界

公开仓库不得包含：

- 真实录音、转写正文或参考正文；
- 成员、样例或内部评测映射；
- 本机路径、模型位置、缓存布局、账号、凭据或网络端点；
- 原始日志、完整异常、私有数量或可逆编码。

公开报告只保留版本、指纹前缀、耗时、测试状态和脱敏摘要。

## 10. Issue bus 协作

每个派单必须写明：

- `dispatch_id` 与目标角色；
- 精确允许文件；
- 验收命令；
- 禁止项与回滚方式。

执行者依次回写 `CLAIM`、`CHECKPOINT`、`HANDOFF` 或固定脱敏的 `BLOCKED`。文件所有权重叠时必须先停止，不能并行修改。

## 11. 冻结与合并

- CI 全绿是必要条件，不是充分条件。
- C 在隐私、契约、测试和组合证据通过后冻结精确 head。
- head 改变即取消旧冻结。
- 合并前按固定顺序做一次只读组合验收。
- 不自动合并、不强制推送；最终操作由明确授权触发。
