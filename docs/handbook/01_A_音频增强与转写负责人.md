# A：音频增强与转写负责人

## 1. 职责

A 负责从输入校验到增强与双路转写的技术闭环，并向 C 提供稳定、可测试的公开契约。A 不负责 UI 布局、公开合并或私有素材发布。

相关入口：

- [项目 README](../../README.md)
- [后端公开契约](../A_BACKEND_CONTRACT_V1.md)
- [冻结 schema](../../core/schemas.py)
- [离线演示手册](../OFFLINE_DEMO_RUNBOOK.md)

## 2. 输入校验与标准化

- 拒绝不存在、为空、损坏或超过公开限制的输入。
- 将可接受音频标准化为 pipeline 约定格式。
- 记录原始格式类别与标准化告警，但不公开原始路径。
- 对静音、削波、重采样和声道变化使用稳定错误码或告警码。

## 3. 增强

`enhance_audio` 生成：

- 完整增强轨；
- 按有限强度混合的 dry/wet 轨；
- 有界耗时、模型身份和告警。

强度必须是 `0.0..1.0` 的有限数值，布尔值、字符串和非有限值一律拒绝。输出必须存在、非空、长度可解释且样本有限。

## 4. 双路转写

`transcribe_audio` 对标准化原轨和混合轨分别运行：

- 语言、模型名和设备由 pipeline 明确传入；
- 输出遵循 `TranscriptResult`；
- segment 的开始、结束和文本字段必须完整；
- 单路失败不得伪造成空成功，应由 pipeline 降级为 partial。

公开日志与 smoke 摘要不得包含转写正文。

## 5. 模型加载

- 模型只在受控入口加载，并在进程内复用。
- 演示前完成资产准备与预热。
- 演示现场不下载、升级或切换模型。
- 对外只报告模型版本、内容指纹前缀、设备类别、冷/热启动和有界耗时。
- 模型位置、缓存布局和完整日志只进入未跟踪的本地私有台账。

## 6. 错误语义

A 层异常必须映射为稳定类型：

- 输入错误；
- 输入过长；
- 增强失败；
- 输出验证失败；
- 转写失败；
- 可视化或可选阶段失败。

异常详情只能保留固定字段、有限数字和异常类型。未知文本、路径、URL、文件名和嵌套自由文本必须 fail-closed 脱敏。

## 7. 测试

必须使用 synthetic 或公开夹具覆盖：

- 合法短音频；
- 损坏、空文件与错误格式；
- 静音、削波、声道与采样率变化；
- 强度边界、布尔值与非有限数值；
- 增强产物为空、长度不一致或非有限；
- 单路转写失败、空转写与 segment 结构错误；
- 冷/热启动与缓存命中；
- 安全 JSON 不含原始文本或路径。

真实模型 smoke 只证明链路可运行；人工听测与用户效果由独立验收完成。

## 8. HANDOFF

公开 HANDOFF 只包含：

- commit 指纹与修改文件；
- 模型版本和指纹前缀；
- 定向/全量测试状态；
- 有界耗时、冷/热启动和设备类别；
- 固定错误码、脱敏问题摘要与回滚指针。

不得回传原始输出、路径、模型位置、素材信息、完整异常或私有文本。

## 9. 禁止项

- 不读取或提交未授权素材。
- 不在公开仓库固化内部评测结构。
- 不修改 B/C 所有文件。
- 不自动合并、不强制推送。
- 文件范围、环境或证据不足时立即固定脱敏 BLOCKED。
