# A 任务书：音频增强与转写负责人

> 项目：听清又听懂·智能音频急救台
> 建议 AI：比赛方 GPT-5.5（几乎无限额度）
> 任务一句话：把任意合法的短音频稳定变成“标准原轨 + 增强轨 + 前后转写 + 可追踪日志”，且任一环节失败时能降级而不拖垮整页。

## 1. 你的最终交付

到 7 月 15 日 11:30，你必须让团队拿到一个可独立验收的音频后端：

```text
输入 10–30 秒 WAV/MP3
  → 转为标准 WAV
  → DeepFilterNet 增强
  → 原轨与增强轨分别 Whisper 转写
  → 产生结构化结果、耗时、警告和可播放文件
```

必须有两种入口：

1. 一个独立命令可处理样例，方便你自测；
2. 一组稳定 Python 函数，供 C 的集成管线调用。

你不交付“一段看起来对的代码”，而是交付“三个样例实际跑过、输出能播放、错误能解释”的模块。

## 2. 负责边界

### 2.1 你负责

- 音频输入校验：文件存在、后缀、时长、声道、采样率、峰值、静音和明显削波。
- 转码与标准化：输出可被 DeepFilterNet 和 Whisper 稳定读取的 WAV。
- DeepFilterNet 加载、推理、延迟补偿和输出写入。
- `dry/wet` 强度混合，并避免 NaN、溢出和明显削波。
- Whisper 原轨/增强轨双路转写，固定中文为演示默认语言。
- 返回标准结果、阶段耗时、模型名称/版本和可恢复错误。
- 三个固定样例的实际基准，包括第一次冷启动与第二次热启动耗时。
- 向 C 稳定提供原始轨路径和音频元数据，供 C 在 P1 中独立尝试 CLAP；A 不实现事件识别。

### 2.2 你不负责

- 不负责 Gradio 布局、配色、页面组件或文案；这些属于 B。
- 不负责修改全局 `ProcessResult` 字段；契约由 C 维护。
- 不负责主分支集成、答辩 PPT、录屏和提交包；这些属于 C。
- 不负责自训模型、实时流、多麦阵列、声源定位或替换三种增强模型做横评。
- 不在没有真实参考文本时伪造 CER，不在没有干净参考音频时声称 PESQ/STOI 提升。

## 4. 必须遵守的输入输出契约

### 4.1 你向 C 提供的函数

```python
normalize_audio(
    input_path: str,
    output_path: str,
    target_sr: int = 48_000,
    mono: bool = True,
) -> AudioMeta

inspect_audio(samples, sample_rate: int) -> dict

load_enhancer(model_dir: str | None = None)

enhance_audio(
    input_wav: str,
    output_full_wav: str,
    output_mix_wav: str,
    strength: float = 0.75,
) -> dict

load_asr(model_name: str, device: str)

transcribe_audio(
    audio_path: str,
    language: str = "zh",
) -> TranscriptResult
```

`strength` 使用 `0.0–1.0` 浮点数，语义为增强轨在最终输出中的比例：

- 轻度：`0.50`
- 标准：`0.75`
- 强力：`1.00`

将 UI 的中文标签映射到数值是 B/C 的事，你不在核心函数中解析“轻度”“强力”。

### 4.2 最低字段

`AudioMeta` 按 `core/schemas.py` 必须包含：

```text
source_name, sample_rate, channels, duration_seconds,
peak_abs, rms_dbfs, clipped_ratio, silent_ratio, normalized_path
```

`enhance_audio` 返回的普通 `dict` 至少包含以下内部调试信息，不再新造公共结果类：

```text
full_output_path, mixed_output_path, strength,
runtime_seconds, model_name, warnings
```

`TranscriptResult` 必须严格使用 `core/schemas.py` 中的以下公共字段，不擅自加义务字段：

```text
text, language, segments, runtime_seconds, model_name, error
```

`segments` 使用以下序列化形式，不返回 Whisper 内部对象：

```json
[
  {"start": 0.0, "end": 2.4, "text": "大家好"}
]
```

### 4.3 错误约定

- 无法读取、时长超限、空文件：抛出 C 在 `core/schemas.py` 约定的可预期输入异常。
- 增强失败：不覆盖原文件；返回或抛出明确阶段错误，供 C 回退到原轨。
- 原轨转写与增强轨转写互不依赖；一路失败不取消另一路结果。
- 所有警告都用机器可读 `code` 和给人看的 `message`；不向用户展示大段 traceback。
- 每次处理都写唯一 `run_id` 目录，绝不覆盖上一次演示成果。

## 5. 实现步骤

### 5.1 第一步：先做运行环境探针

不要一上来就把全部依赖写进一个大文件。先保存以下结果：

```text
Python 版本
操作系统和 CPU/GPU 类型
ffmpeg 是否可用
DeepFilterNet 是否可导入
Whisper 是否可导入
模型权重是否已缓存
空闲磁盘空间
```

验收：用 1–3 秒 WAV 完成一次最小推理，而不是只做 `import`。

### 5.2 第二步：音频标准化

1. 把 MP3/M4A/FLAC 转成 WAV；
2. 多声道在 P0 中下混为单声道，保留原始元数据；
3. DeepFilterNet 主路使用其需要的采样率，Whisper 端由库或明确预处理适配；
4. 诊断静音、过长、极低音量、高削波比例；
5. 保留一份标准化原轨用于 A/B，不在原用户文件上就地改写。

验收样例：双声道 WAV、44.1 kHz WAV、MP3、全静音 WAV、超时长 WAV、损坏文件各一个。

### 5.3 第三步：DeepFilterNet 增强

1. 模型单例加载，避免每次点击都重载权重；
2. 推理前后使用单调时钟记录耗时；
3. 优先使用库的官方 Python API，不用解析 shell 文本作为核心接口；
4. 用对齐后的 dry 和 wet 做线性混合；
5. 混合后检测非有限值、峰值和削波比例；
6. 若需峰值安全缩放，缩放原因必须写入警告；
7. 不用“输出更响”制造假改善。A/B 比较的响度匹配规则与 C 一起确认。

验收：三个样例都生成可播放 WAV；无 NaN/Inf；无明显爆音；轻度、标准、强力三种输出不是同一文件的伪复制。

### 5.4 第四步：Whisper 前后转写

1. P0 只加载一个多语言模型；先测 `base`，超过现场耗时预算再降到 `tiny`；
2. 中文主演示显式指定 `language="zh"`，不用 `.en` 模型；
3. 原轨与增强轨各自捕获错误；
4. 返回纯文本和精简分段，删掉不可序列化对象；
5. 固定样例可做内容哈希缓存，但 UI 必须明确显示“缓存结果”；
6. 不做文本后编辑来假装 ASR 改善；只可以做空白正规化等前后一致的展示处理。

验收：对每个主样例输出 before/after 文本、分段、语言、模型和耗时；增强后如果变差也如实交付。

### 5.5 第五步：缓存和离线化

- 在 7 月 15 日晚锁定模型权重和缓存路径。
- 用断网测试证明模型不会现场再下载。
- 固定样例缓存包含输入哈希、模型版本、参数和结果；任一关键值不同就不命中。
- 保留一份可立即演示的预计算结果，但不把它包装成现场推理。

## 7. GPT-5.5 的使用方式

几乎无限额度最适合高频、短闭环：**一个小任务 → 运行真实命令 → 读取错误 → 最小修复 → 回归**。不要一口气让它“写完整个后端”。

### 提示词 A1：实现单个函数

```text
你是本项目的音频后端工程师。先阅读 PROJECT_GUIDE.md 和 core/schemas.py。
本次只实现 core/enhance.py 中的 enhance_audio，不要修改其他人拥有的文件。
输入/输出必须严格遵守契约。
要求：模型单例加载；dry/wet 0–1；非有限值、削波检查；不覆盖输入。
请先描述最小修改计划，然后修改代码，运行相关测试和一次真实短音频 smoke test。
最后只汇报：改了哪些文件、哪些测试通过、真实耗时、剩余风险。
```

### 提示词 A2：根据报错做最小修复

```text
以下是可重现的报错、运行命令和环境信息：
<粘贴精简信息>
先说出最可能的 1–3 个原因和如何区分，不要直接大改。
只允许修改：<列出 A 拥有的文件>。
优先修复根因；不要降低契约、不要吞掉异常、不要加入未申请的新依赖。
修改后重跑失败用例和相关回归，并报告证据。
```

### 提示词 A3：让 AI 设计边界测试

```text
审查 core/audio_io.py、core/enhance.py、core/transcribe.py，不修改生产代码。
为下列风险设计最小测试集：空文件、静音、双声道、超长、极低音量、削波、模型加载失败、一路 ASR 失败。
单元测试不下载模型；另提供一个显式调用的真实 smoke test。
仅修改 tests/test_audio_io.py、tests/test_enhance.py、tests/test_transcribe.py 和 scripts/smoke_audio_core.py。
```

## 10. 失败降级

| 问题 | 你立即采取的降级 | 不允许的反应 |
|---|---|---|
| DeepFilterNet 在一台机器安装失败 | 使用已成功机器生成固定样例增强缓存；保留原轨和明确警告 | 现场同时换 GTCRN、AudioSep、MossFormer |
| Whisper `base` 太慢 | 降到多语言 `tiny`，限制演示到 10–15 秒，缓存固定样例 | 临时上云 API 并依赖现场网络 |
| 增强后 ASR 变差 | 降低 strength，如实标记负例，锁定更稳定主样例 | 人工修改转写文本来制造提升 |
| M4/CPU 内存压力大 | 串行处理，一次只保留必需模型，由 C 关闭 CLAP，A 的 ASR 使用 tiny | 并行加载多个大模型 |
| 输入格式奇怪 | 只保证 WAV/MP3 P0；其他格式给明确转换提示 | 为罕见格式破坏主链 |
| C 的 CLAP P1 不稳定 | 保持 A 的 P0 接口不变，协助确认原轨可读后由 C 关闭 P1 | 越权修改 `core/events.py` 或用手工标签冒充模型输出 |
