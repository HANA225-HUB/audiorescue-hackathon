> 项目：听清又听懂·智能音频急救台
> 建议 AI：比赛方 GPT-5.5（几乎无限额度）
> 任务一句话：把 C 给出的结构化处理结果，变成评委 10 秒看懂、5 分钟内演示完、后端部分失败也不会白屏的产品页。

## 1. 你的最终交付

最终页面只讲一个故事：

```text
选择/上传一段嘲杂语音
  → 点击“开始急救”
  → 先听原音，再听增强音
  → 看前后声谱图
  → 看前后转写差异
  → 理解处理耗时、限制和可下载结果
```

必须交付：

- 一条命令启动的 Gradio 页面；
- 上传和至少 3 个本地固定样例入口；
- 并排的原音/增强音播放器；
- 前后波形或声谱图，以声谱图为主；
- 前后转写和明确的文本差异；
- 加载中、成功、部分成功、失败四类状态；
- 处理耗时、输入信息、警告和导出入口；
- 现场断网仍能打开、不依赖外部 CDN 的稳定版。

## 4. 页面固定结构

### 4.1 首屏：10 秒内懂

从上到下固定为：

1. 项目名：**听清又听懂·智能音频急救台**；
2. 副标题：“把嘲杂录音一键变成可听、可读、可解释的结果”；
3. 流程条：`1 上传 → 2 急救 → 3 听感 → 4 证据`；
4. 左侧输入区：固定样例、上传/录音、增强强度、参考台词（可选）；
5. 右侧操作区：一个醒目的“开始急救”按钮、预估说明、当前状态。

首屏不放模型学术介绍、依赖列表或大段原理。

### 4.2 结果区：按演示顺序排列

1. **A/B 听感**：左侧“处理前”，右侧“增强后”；
2. **可视化证据**：前后声谱图使用相同配色、频率范围和 dB 颜色范围；
3. **转写证据**：前后文本并排，再展示差异和可选 CER；
4. **运行证据**：增强、前后 ASR、可视化和总耗时；
5. **警告/限制**：黄色展开区，简短、诚实、不用技术堆栈；
6. **导出**：增强 WAV、转写 TXT 和结果 JSON，若 C 已提供。

### 4.3 页尾

只需包含：

- 使用的预训练模型与团队完成的工程部分；
- “当前为录制后准实时处理，不是流式实时”；
- 直到现场确实测过之前，不写“毫秒级”“实时”“百分百”。

## 5. 与 C 的接口契约

### 5.1 你只调用一个顶层函数

```python
process_audio(
    input_path: str,
    strength: float = 0.75,
    enable_events: bool = False,
    reference_text: str | None = None,
    force_recompute: bool = False,
) -> ProcessResult
```

你不从 `app.py` 直接调用 A 的多个函数。否则页面将承担调度、错误和模型生命周期，很快变成无法测试的“万能文件”。

### 5.2 你读取的结果字段

```text
job_id
status = success | partial | failed
input_meta = AudioMeta | None
original_audio_path, enhanced_audio_path
transcript_before, transcript_after = TranscriptResult | None
cer_before, cer_after = CerResult | None
text_diff_html
waveform_path, spectrogram_path
events = list[EventResult]
runtime = RuntimeStats
warnings = list[WarningItem]
config_snapshot = dict
```

每个可选字段都需要缺失状态。不得因为 `cer_before/cer_after` 为空就让页面报错。

### 5.3 前端展示矩阵

| 状态 | 音频 | 声谱图 | 转写 | 文案 |
|---|---|---|---|---|
| `success` | 前后都播放 | 前后都显示 | 前后都显示 | 绿色“急救完成” |
| `failed`，增强阶段失败 | 可播放原轨，增强位置显示失败 | 可只显示原轨 | 保留已得到的原轨转写 | 红色“增强未完成”，可换样例重试 |
| `partial`，一路 ASR 失败 | 前后仍播放 | 前后仍显示 | 失败侧显示原因，不伪造文本 | 黄色“音频已完成，部分转写不可用” |
| `failed`，输入不可解码 | 不播放或仅保留浏览器可预览原文件 | 不显示伪空图 | 不显示 | 红色但可操作的换文件提示 |
| 缓存 | 正常 | 正常 | 正常 | 明确小标识“本地缓存” |

## 6. 可视化的技术规则

### 6.1 声谱图

- 前后使用相同 `n_fft`、`hop_length`、频率上限、色带和 dB 范围。
- 前后时长不同时，页面显示警告，不用拉伸图像伪装对齐。
- 坐标轴用“时间/秒”和“频率/Hz”或“kHz”，不留默认英文缩写让评委猜。
- 标题明确写“原始轨”和“增强轨”。
- 声谱图只用于说明能量分布变化，页面不将“图更干净”直接写成“质量一定更高”。

### 6.2 A/B 公平性

- 音频播放器上方注明是原轨还是增强轨。
- 页面不用不同初始音量诱导听感。
- 如果后端做了响度匹配，可在详情中说明；如果没有，不写“公平对比”。
- 不做自动循环播放，不使用全屏音效。

### 6.3 文本差异

- 中文可先做字级 diff，对中英混合内容需保留连续英文词。
- 绿色/红色之外还要有文字或下划线，不只依赖颜色。
- 没有参考文本时，diff 仅表示“两次 ASR 输出不同”，不把 after 的新字当成正确修复。
- 有参考文本时，展示 `CER before → CER after`；只显示 C 管线已计算的值，UI 不自行重算另一套。

### 6.4 性能与缓存

- 图像保存为当次 `run_id` 下的本地 PNG，避免不同次运行串图。
- 演示模式优先使用固定尺寸，不为超高分辨率拖慢页面。
- 图像生成失败时，不影响 A/B 和转写显示。

## 12. 失败降级

| 问题 | 降级方式 |
|---|---|
| 真后端未就绪 | 持续用契约 fixture 开发，只在集成时换回调；不伪装已完成真模型 |
| 声谱图生成慢 | 对固定样例缓存 PNG，降低图像分辨率；保留音频与转写 |
| Plotly/前端依赖不稳 | 回退到 matplotlib 静态 PNG，不为可交互图破坏离线演示 |
| 文本 diff 中英混合错乱 | 回退到前后文本并排 + 简单字级标记，不阻塞 P0 |
| 页面美化与稳定性冲突 | 删动画、删外部字体/CDN、回到 Gradio 默认组件 |
| 麦克风权限失败 | 上传和固定样例仍是主路，录音入口标注为可选 |
| 页面无法在投影分辨率显示 | 使用 100% 缩放、两列变单列或折叠详情，不临时重写 |
