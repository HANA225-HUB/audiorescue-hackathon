# AudioRescue 两天执行包

> 项目名：**听清又听懂·智能音频急救台**
> 比赛范围：只服务当前 Vibe Coding 黑客松
> 执行窗口：2026-07-14 晚至 2026-07-16 17:00
> 唯一 P0：上传/录制噪声音频 → 语音增强 → 增强前后转写 → A/B、声谱图与文本差异

## 1. 先读结论

未来两天只围绕下面这条链路工作：

```text
10–20 秒中文噪声音频
  → 输入检查与标准化
  → DeepFilterNet 增强
  → Whisper 对原始轨和增强轨分别转写
  → A/B 播放 + 前后声谱图 + 文本差异 + 处理耗时
```

项目完成的判定不是“模型都装上了”，而是：

1. 在最终演示机上断网也能启动；
2. 至少两个固定样例能稳定跑完整链路；
3. 原始音频和增强音频音量公平，可直接 A/B；
4. 页面能说明处理前后转写发生了什么变化；
5. 任一可选模块失败时，P0 仍能完成；
6. 五分钟内完成一次不慌乱的现场演示。

## 3. 三人默认分工

| 成员 | AI 条件 | 主责任 | 为什么这样分 |
|---|---|---|---|
| A | 比赛方 GPT-5.5，额度近乎无限 | 音频后端：格式统一、DeepFilterNet、Whisper、音量与输出文件 | 安装、报错修复、脚本迭代和批量样例测试调用频繁，适合高吞吐迭代 |
| B | 比赛方 GPT-5.5，额度近乎无限 | 前端与可视化：Gradio、状态反馈、A/B、图表、文本差异、样例入口 | UI 需要大量小步修改、运行、截图、复测，同样适合高频调用 |
| C（用户/队长） | 官方 GPT Pro，可用 GPT-5.6 Sol | 架构、接口、集成、Code Review、跨模块故障、质量门槛、演示叙事 | 把更强的长上下文推理用于全局一致性和难问题，而不是消耗在重复按钮微调上 |

这不是按模型给人“排能力”。人的经验优先于型号。今晚先做 20 分钟客户端能力试跑：三个人分别让自己的 AI 完成同一段小函数、一个已知报错诊断和一次改动审查；根据实际工具权限、响应速度和代码通过率交换 A/B，也可由更懂 Python 的人接 A。

OpenAI 的 API 模型页将 GPT-5.5 与 GPT-5.6 Sol 都列为文本/图像输入、文本输出，音频不属于其直接输入模态。因此不要让编码模型代替人耳判断增强效果，也不要让它“凭描述听音频”。AI 负责代码、日志、图表和推理；Whisper 负责转写；三名成员必须亲自做 A/B 盲听。比赛方安装版或 ChatGPT 客户端可能额外封装工具，但只能以 20 分钟实测结果为准。

### 绝对协作规则

- 一名成员只让自己的 AI 修改自己拥有的文件。
- 同一时刻不得让两个 AI 客户端编辑同一文件。
- 公共接口先写进文档，再写实现；更改公共接口必须由 C 确认。
- 每次 AI 改动只解决一个可验收问题，改后立即运行最小测试。
- 任何人交接的必须是“命令 + 输入 + 输出 + 已知问题”，不能只发一段代码。
- 7 月 16 日 10:00 后停止新增功能，14:00 后只修会阻断演示的问题。

## 4. 服务器结论

**默认不租服务器。** 当前 P0 是推理任务，DeepFilterNet 和 Whisper `tiny/base` 可以先在 Apple M4、16GB 机器上串行运行。比赛现场最危险的是网络与远端服务，不是缺少更大的 GPU。

但该 Mac 当前只剩约 12GB 可用空间。开始安装前，机主应先自行确认并额外腾出约 15–25GB；只清理明确可删除的下载、缓存或旧构建，不在不知用途时批量删除。模型和演示素材全部在 7 月 15 日晚前缓存到本地。

2026-07-14 的本机预检发现：默认 Python 可能不是项目目标版本，FFmpeg 也可能缺失。今晚应先安装 FFmpeg，再显式用 Python 3.10 或 3.11 创建项目虚拟环境，不要直接在不兼容的系统 Python 中装依赖。

只有出现以下任一情况才租卡：

1. 10–15 秒样例在演示机上完整处理明显超过目标时间，且换 `tiny/base` 仍不可接受；
2. Apple Silicon 上出现无法在 60–90 分钟内解决的依赖或算子兼容问题；
3. P1 的模型导致内存压力，但团队已决定 P1 值得保留；
4. 需要一台干净 Linux 环境做构建验证或离线预计算备份。

国内优先考虑单张 RTX 3090 24GB；想用更少等待时间再选 RTX 4090 24GB。建议至少 8 vCPU、32GB 内存、50–80GB 系统盘和约 50GB 数据盘。服务器只承担测速、预计算或备份，不作为现场页面的联网后端。

## 5. 今晚开始后的前 90 分钟

### 0–20 分钟：锁定人与规则

- 填好 A/B/C 的真实姓名；
- 完成三个 AI 客户端能力试跑；
- 选择最终演示机；
- C 宣读 P0、不做事项、接口变更规则；
- 建代码仓库与 `PROJECT_GUIDE.md`。

### 20–60 分钟：三线独立跑通

- 环境前置：安装 FFmpeg，然后用 Python 3.10 或 3.11 创建独立环境；
- A：用一段 10 秒 WAV 跑通 DeepFilterNet，并保存增强 WAV；再让 Whisper 分别输出两段文本。
- B：用假数据完成 Gradio 页面骨架，能上传、播放两段音频并展示两张占位图和两段文本。
- C：冻结 `process_audio(...)` 参数、`ProcessResult`、目录、错误码和验收样例，建立集成桩函数。

### 60–90 分钟：第一次集成

- A 只通过约定接口交付，不把模型对象泄漏给 UI；
- B 用真实 `ProcessResult` 替换假数据；
- C 执行一条完整链路，并记录首个耗时基线；
- 成功后立即保存一个可回退版本。

90 分钟验收底线：哪怕页面很丑，选择一个固定样例后也必须能得到增强音频，或至少得到增强前后两段转写；不能三个人都停留在“环境还没装好”。

## 6. 最终技术选择

| 项目 | 当前选择 | 变更门槛 |
|---|---|---|
| Python | 3.10 | 不在比赛中追新版本 |
| UI | Gradio | 只有安装完全失败才考虑 Streamlit |
| 语音增强 | DeepFilterNet | 不并行尝试多套增强模型 |
| ASR | OpenAI Whisper 多语言 `tiny` 或 `base` | 用同一批样例实测后一次性锁定；中文不用 `.en` |
| 图表 | matplotlib 优先 | 页面确有交互需求再用 Plotly |
| P1 | CLAP 固定 8–12 个候选标签 | 不得阻塞或改变 P0 接口 |
| 部署 | 本地运行、断网可用 | 云端只作后备 |
