## 唯一完成标准

项目只有在以下门禁全部通过后，才能交给用户做正式效果测试：

- 公开 schema 与 UI 调用契约一致；
- 轻量单测、全量单测、静态隐私检查和浏览器离线检查通过；
- 固定组合 heads 无冲突，且检查结果可复现；
- 真实模型 smoke 与 synthetic/fixture 门禁被明确区分；
- 公开文档不含私有内容、绝对路径、缓存布局或环境凭据；
- 当前树已经冻结，回滚顺序和未决风险已记录；
- 未执行自动合并，最终合并由 C 与用户共同决定。

## 角色边界

### A：音频与模型

- 输入校验、标准化、增强与双路转写；
- 输出格式、模型身份、运行耗时与错误语义；
- 使用 synthetic 夹具完成可复现测试；
- 不在公开渠道回传原始内容、路径或模型位置。

### B：界面与交付

- 上传、参数、状态、播放器、图表与文本差异；
- 不透明本地 URL、范围请求、过期清理和 fail-closed 降级；
- 离线资源检查和浏览器首屏验收；
- 不把夹具测试描述为真实效果证据。

### C：集成与冻结

- 公共 schema、pipeline 入口和跨模块契约；
- 任务路由、文件所有权、审查、冻结与回滚；
- 组合验收、公开证据与最终测试版本；
- 隐私事件先停止发布，再进行当前树缓解；历史处理需用户授权。

## 证据口径

公开证据只包含：

- 版本或提交指纹前缀；
- 测试数量与通过状态；
- 有界耗时、设备类别和冷/热启动标记；
- 固定错误码、脱敏问题摘要与回滚指针。

原始输出、素材信息、路径、模型位置和完整日志只能进入未跟踪的本地私有台账。

## 冻结纪律

1. 一个冻结结论只对应一个精确 head。
2. head 变化后必须重新检查，旧冻结立即失效。
3. PR 可以通过 CI 但仍因隐私、契约或证据问题被阻止。
4. 可选工具不得阻塞核心演示，但也不得绕过其独立门禁。
5. 不自动合并、不强制推送、不在公开评论中粘贴敏感命中内容。
