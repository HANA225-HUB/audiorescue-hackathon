## 1. 主链路发布门槛

正式主演示必须同时满足：

1. 本地断网可启动；
2. approved short sample 可重复完整处理；
3. 原始轨和增强轨可播放；
4. 两轨使用同一 ASR 配置；
5. success/partial/failed 状态准确；
6. 页面不泄露路径、堆栈、凭据、私有文本或 token URL；
7. 外部请求为零；
8. delivered files 使用受控 opaque route；
9. 处理耗时进入演示可接受范围；
10. 失败时能切换到本地 fallback。

如果任何一项不满足，必须降级或改写演示表述，不得隐藏失败。

## 2. 测试数据公开口径

数据制作和私有台账规则见 [07_数据集与演示样例制作手册.md](07_数据集与演示样例制作手册.md)。

公开可写：

- synthetic fixture;
- approved short sample;
- private ledger;
- demo candidate;
- reserved evaluation set;
- local fallback.

公开不可写：

- 私有台词或转写文本；
- 成员、场景、噪声或样例映射；
- 真实录音文件名、路径、数量或哈希；
- 保留评测数据细节；
- 私有听感备注或逐样例指标；
- 服务器、缓存、模型路径或凭据。

## 3. 自动化测试入口

轻量检查：

```bash
python -m py_compile app.py core/*.py ui/*.py scripts/*.py
python -m unittest discover -s tests -p "test_*.py" -q
git diff --check
```

文档和仓库安全检查：

```bash
python -m unittest -v tests.test_repo_safety
```

完整 smoke 只在模型资产和 approved short sample 已准备好后运行：

```bash
python scripts/smoke_audio_core.py --normalize-only
python scripts/smoke_audio_core.py --runs 2 --asr-model base --device auto
```

公开报告只写命令、通过数量、跳过数量和安全摘要。

## 4. UI 验收

UI 验收必须覆盖：

- 上传或录音入口可见；
- 增强强度控件可见；
- 开始按钮可见；
- 处理中说明可见；
- 状态区可见；
- success、partial、failed 有文字和样式区分；
- 音频播放器标签清晰；
- 下载入口使用中性文件名；
- 波形和声谱图不溢出；
- 文本差异和 CER 区域不会遮挡；
- 错误提示为固定公开语义；
- 刷新后仍可使用。

fixture 只能证明页面状态、离线资源和交互，不证明真实增强或识别效果。

---

## 5. 音频质量验收

真实效果由人工和安全摘要共同判断：

- 输出 WAV 可解码；
- 采样率、声道和 PCM 格式符合契约；
- 样本有限且无 NaN/Inf；
- 无明显新增削波；
- 原轨与增强轨播放音量策略一致；
- 人工听感记录由 C 汇总；
- 有私有参考时可计算 CER，但公开只发布安全摘要。

如果增强后效果更差，不得隐藏。应展示 partial/failed 或明确说明该候选未通过。

## 6. 断网与资源验收

断网前：

- 模型资产已预热；
- approved short sample 已确认授权；
- fallback 已准备；
- 依赖检查通过；
- 本地页面可打开；
- 外部资源检查通过。

断网后：

- 生产 fixture 关闭；
- 本地页面启动；
- approved short sample 可处理；
- 外部请求为零；
- delivered files 的 HEAD/GET/Range 正常；
- 错误状态不会白屏；
- 临时资源可清理。

现场禁止联网下载、裸升级、换模型或调代码。

## 8. 演示台本

公开台本只描述动作：

1. 打开本地页面；
2. 选择 approved short sample；
3. 设置增强强度；
4. 点击开始；
5. 播放原轨和增强混合轨；
6. 展示双路转写、diff、可视化和状态；
7. 下载安全产物；
8. 切换 fallback 说明；
9. 关闭服务并清理本轮临时资源。

台上不展示私有台账、真实文件名、参考文本、服务器信息、缓存路径或原始日志。

## 9. 故障处置

| 故障 | 处置 |
|---|---|
| 模型资产不可用 | 停止真实处理，使用同版本 fallback |
| 转写为空 | 如实展示为空，不手动补文本 |
| partial | 展示可用产物和安全 warning |
| failed | 展示结构化失败，不公开 raw log |
| 外部请求异常 | 切本地 fallback，不现场联网下载 |
| 性能超时 | 切短样例或 fallback |
| 音频质量不佳 | 明确该候选未通过，不夸大效果 |

---

## 10. Go / No-Go

Go：

- 代码和文档门禁通过；
- PR 状态和 draft/merge 边界明确；
- fixture 与真实效果边界明确；
- approved short sample 已通过私有台账检查；
- 三人知道失败口径。

No-Go：

- 公开文档含私有数据细节；
- 页面泄露路径或 raw exception；
- partial/failed 被包装成完整 success；
- 现场依赖联网下载；
- 未合并 PR 被写成 main 已包含或比赛 ready。
